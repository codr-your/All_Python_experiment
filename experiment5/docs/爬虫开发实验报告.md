# 二、爬虫开发实验报告

## 1 实验目的
掌握 Vibe Coding 核心工作流：意图定义、任务拆解、验证闭环，改变直接一次性写完整代码的开发习惯。
学会编写结构化 Prompt，驱动 AI 生成基于requests+BeautifulSoup的 Python 静态网页爬虫代码。
掌握 AI 生成代码的审查、调试、重构能力，建立爬虫反爬与网络合规意识。

## 2 实验环境
Python 版本：Python3.9 及以上
AI 编程工具：Cursor / GitHub Copilot
第三方依赖库：requests、beautifulsoup4、pandas
开发平台：Windows，代码托管平台 GitHub

## 3 实验任务
抓取公开新闻列表网页，提取文章标题、发布时间、作者、文章链接四个字段；
采用 Vibe Coding 迭代开发流程：需求澄清 → 分步生成代码 → 运行验证调试 → 异常处理持久化 → 代码审查重构；
最终数据保存为result.csv结构化文件，终端打印抓取成功条数。
Vibe Coding 约束：禁止直接让 AI 一次性输出全部完整代码，必须分阶段生成，每一步运行验证，报错后将报错信息反馈 AI 修复代码。

## 4 实验原理
requests 库：模拟浏览器发送 HTTP GET 请求，设置 User‑Agent 伪装浏览器身份，设置超时、重试机制，降低被网站反爬拦截概率；设置请求间隔，避免高频访问服务器。
BeautifulSoup4：解析返回 HTML 文本，遍历 DOM 节点，定位并提取目标字段。
pandas 库：将列表字典格式数据写入 csv 文件，处理 UTF‑8 编码，兼容中文。
Vibe Coding 开发思想：不直接生成完整大代码，拆分最小可运行单元，每一步运行、验证，有错误就把报错 Traceback 交给 AI 迭代修复，逐步叠加功能，最后整体重构为面向对象类。

## 5 实验步骤与过程
### 步骤 5.1 需求澄清：编写结构化 Prompt
不简单说 “帮我写爬虫”，按照角色 + 目标 + 约束 + 验收标准编写提示词。
使用 Prompt 原文：
你是 Python 后端工程师。我需要编写一个静态网页爬虫。目标：抓取【目标网站 URL】的列表页，提取标题、时间、作者、链接。约束：使用 requests 和 BeautifulSoup；必须设置 User‑Agent 伪装；请求间隔不低于 2 秒；遇到网络超时需重试 3 次。验收：输出 result.csv 文件，并在终端打印成功抓取条数。

### 步骤 5.2 分步生成，最小单元验证
阶段 1：仅生成发送网络请求代码（step1_request.py）
只让 AI 输出发送 HTTP 请求、获取 HTML 的代码，不写解析逻辑。
运行代码，观察打印状态码，确认返回状态码为 200，成功拿到网页 HTML 文本。
如果发生超时、连接报错，复制完整 Traceback 报错信息，反馈给 AI 修复重试逻辑。
截图位置：images/run_request.png
阶段 2：增加 HTML 解析逻辑（step2_parse.py）
请求模块跑通之后，再让 AI 增加解析 HTML 的代码；运行后打印前 3 条解析结果，核对标题、时间、作者、链接字段提取是否正确；字段缺失、标签定位错误，把打印输出交给 AI 修正选择器。

### 步骤 5.3 数据持久化与异常容错处理
要求 AI 增加 csv 写入逻辑，同时增加异常处理：当网页中某个字段缺失时，赋值为空字符串，避免程序直接崩溃终止。
运行完整脚本，检查输出output/result.csv：
文件编码为 UTF‑8，中文不乱码；
csv 表头列名：标题、发布时间、作者、链接；
每一行数据对齐，无错位。

### 步骤 5.4 代码审查，工程化面向对象重构
将前面所有迭代完成的过程式完整代码全部复制，发送给 AI，使用审查重构 Prompt：
“请审查这段代码，指出潜在的性能瓶颈或安全隐患，并将其重构为面向对象的类结构（如 NewsCrawler 类），保持功能不变。”
AI 分析指出潜在隐患：缺少会话复用、异常捕获不全、硬编码参数较多；将全部逻辑封装NewsCrawler类，把请求头、重试次数、延时时间、目标 url 作为类的属性。
运行重构后的crawler.py，验证：功能与原来完全一致，同样输出 result.csv，抓取条数打印正常，代码可读性明显提升。

### 步骤 5.5 进阶挑战思考：动态渲染网页爬取
静态页面 requests 直接获取 HTML 即可拿到全部数据；Vue/React 动态渲染网页，页面原始 HTML 没有数据，数据是浏览器执行 JS 之后渲染生成。
两种实现方案对比：
表格
方案	实现工具	代码复杂度	运行效率
方案 1：浏览器自动化	Selenium / Playwright	高，需要启动浏览器，配置驱动	低，启动浏览器开销大，速度慢
方案 2：直接抓后端接口	requests 模拟请求后端 AJAX 接口	中等，需要抓包分析接口参数	高，直接拿 json，不需要加载页面渲染
结论：动态网页优先寻找后端 api 接口；找不到接口，再使用浏览器模拟方案。

## 6 实验结果
程序可以正常请求目标网页，设置 User‑Agent、2 秒请求间隔，超时自动重试 3 次。
成功提取新闻列表的标题、发布时间、作者、链接；字段缺失时不会程序崩溃。
输出result.csv，UTF‑8 编码中文正常，终端输出打印成功抓取的数据条数。
代码重构完成NewsCrawler面向对象类，代码结构清晰，可维护性增强。

## 7 实验遇到问题与解决
### 问题 1：直接运行被网站 403 拒绝访问
解决：增加浏览器 User‑Agent 请求头伪装，不能使用 requests 默认 UA。
### 问题 2：部分新闻没有作者，程序直接抛出异常终止
解决：增加判断，找不到节点返回空字符串，做容错处理。
### 问题 3：csv 打开中文乱码
解决：pandas 保存设置encoding="utf‑8‑sig"。
### 问题 4：一开始直接让 AI 写完整爬虫，代码一堆 bug，很难定位
解决：遵循 Vibe Coding，切分成最小模块分步写，每一步验证，报错再交给 AI 修复。

## 9 实验总结
本次实验学习 Vibe Coding 开发模式，不依赖 AI 一次性输出完整可用代码，而是需求澄清 — 分模块生成 — 运行验证 — 反馈报错迭代的闭环开发流程。
学会使用 requests+BeautifulSoup 完成静态网页数据抓取，理解爬虫的反爬基础策略：UA 伪装、请求延时、重试、异常容错。
同时完成代码审查与面向对象重构，体会过程式代码转为类封装之后代码可读性提升。
实验也建立爬虫合规意识，不能高频暴力访问网站，要尊重网站 robots 协议。针对 JS 动态渲染网页，区分接口抓取和浏览器渲染两种不同实现思路。
